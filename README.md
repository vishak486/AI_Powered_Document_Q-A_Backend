# DocuMind AI – Backend

REST API for **DocuMind AI**, an app that lets you upload PDF documents and ask questions about them. It uses Retrieval-Augmented Generation (RAG): PDFs are split into chunks, converted to vector embeddings, stored in MongoDB Atlas, and the most relevant chunks are sent to Gemini to produce an answer grounded in the document.

**Live API:** https://documindaiserver.runasp.net/

## Features

- Upload PDF files (up to 10 MB) and process them automatically
- Text extraction and chunking (1000 characters with 200 overlap)
- Embeddings with Google Gemini (`gemini-embedding-001`, 768 dimensions)
- Semantic search with MongoDB Atlas Vector Search
- Answers generated by Gemini using only the retrieved context
- Model fallback with request timeouts, so a slow model doesn't hang the request
- Per-document chat history
- Document listing and deletion (removes the document's chunks too)

## How It Works

**Upload**

1. A PDF is received and its text is extracted
2. The text is split into overlapping chunks
3. Each chunk is embedded with Gemini
4. Chunks and vectors are saved to MongoDB, and the document is marked `ready`

**Ask a question**

1. The question is embedded with Gemini
2. Atlas Vector Search finds the 3 most similar chunks (optionally limited to one document)
3. The chunks are sent to Gemini as context
4. The answer is returned with its sources and saved to the chat history

## Getting Started

### Prerequisites

- Node.js 22 or later
- A MongoDB Atlas cluster
- A Google Gemini API key

### Installation

```bash
git clone https://github.com/vishak486/AI_Powered_Document_Q-A_Backend.git
cd AI_Powered_Document_Q-A_Backend
npm install
```

### Environment variables

Create a `.env` file in the project root:

```env
DBCONNECTIONSTRING=your_mongodb_atlas_connection_string
GEMINI_API_KEY=your_gemini_api_key
PORT=3000
```

`PORT` is optional and defaults to `3000`. Never commit your `.env` file.

### MongoDB Atlas Vector Search index

Create a Search index on the `chunks` collection named `vector_index`:

```json
{
  "fields": [
    {
      "type": "vector",
      "path": "embedding",
      "numDimensions": 768,
      "similarity": "cosine"
    },
    {
      "type": "filter",
      "path": "documentId"
    }
  ]
}
```

The dimensions must stay at `768` to match the embedding model and the `Chunk` schema. The `documentId` filter field is needed to ask questions about one specific document.

### Run

```bash
npm run dev     # development with nodemon
npm start       # production
npm run lint    # run ESLint
```

The server starts on `http://localhost:3000`.

## API Endpoints

| Method | Endpoint | Description |
| --- | --- | --- |
| GET | `/` | Health check |
| POST | `/api/documents/upload` | Upload a PDF (multipart form field `file`) |
| POST | `/api/documents/ask` | Ask a question |
| GET | `/api/documents` | List all documents |
| DELETE | `/api/documents/:id` | Delete a document and its chunks |
| GET | `/api/documents/:id/chat-history` | Get chat history for a document |

### Upload a document

```bash
curl -X POST http://localhost:3000/api/documents/upload \
  -F "file=@your-document.pdf"
```

Response:

```json
{
  "message": "Document uploaded and processed successfully",
  "document": {
    "id": "6af2e0d4614c071d8f76fde0",
    "filename": "your-document.pdf",
    "totalChunks": 8,
    "status": "ready"
  }
}
```

### Ask a question

`documentId` is optional. Leave it out to search across all documents.

```bash
curl -X POST http://localhost:3000/api/documents/ask \
  -H "Content-Type: application/json" \
  -d '{"documentId":"6af2e0d4614c071d8f76fde0","question":"What is this document about?"}'
```

Response:

```json
{
  "answer": "…",
  "sources": [
    { "chunkIndex": 0, "score": 0.85, "preview": "…" }
  ]
}
```

Chat history is saved only when `documentId` is provided.

## Deployment (MonsterASP.NET)

The API runs on MonsterASP.NET using the **Node.js SSR app** Git deployment type.


## Continuous Integration

GitHub Actions (`.github/workflows/ci.yml`) runs on every push and pull request to `main` or `master`. It installs dependencies with `npm ci` and runs `npm run lint`.
